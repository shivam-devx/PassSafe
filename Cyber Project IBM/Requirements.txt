--------------------------------------------------------------
1. PROJECT TITLE
--------------------------------------------------------------
PassSafe — Password Security Checker


--------------------------------------------------------------
2. OBJECTIVE
--------------------------------------------------------------
To build a simple, client-side web application that helps
users understand and improve their password security. The
tool allows users to check how strong a password is, generate
a new secure random password, and learn basic password safety
tips — all without sending any data over the internet.


--------------------------------------------------------------
3. PROBLEM STATEMENT
--------------------------------------------------------------
Many people use weak or repeated passwords because they do
not know what makes a password secure. There is a need for
a simple, free, and private tool that:
  - Tells users whether their password is weak, medium, or strong
  - Explains what is missing from their password
  - Generates a strong password they can use immediately
  - Educates users about good password habits

This project addresses that need using only a web browser,
with no server, no account, and no data collection.


--------------------------------------------------------------
4. FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------
FR1 — Password Strength Checker
  - The user can type a password into a text input field.
  - The user can click a Show/Hide button to toggle whether
    the password is visible or hidden (masked).
  - After clicking "Check Password", the system analyses the
    password locally in the browser.
  - The system scores the password on five criteria:
      a. Contains at least one lowercase letter (a–z)
      b. Contains at least one uppercase letter (A–Z)
      c. Contains at least one number (0–9)
      d. Contains at least one special character (e.g. !, @, #)
      e. Is 12 or more characters long
  - Based on the score (0–5 points), the system assigns a level:
      Score 0–2 : Weak   (red bar, 33% width)
      Score 3   : Medium (orange bar, 66% width)
      Score 4–5 : Strong (green bar, 100% width)
  - Common words, predictable sequences, and four-or-more
    repeated characters override the score and are rated Weak.
  - A coloured animated progress bar shows the strength visually.
  - A label displays the strength level ("Weak", "Medium", or
    "Strong") in the matching colour.
  - One or more short improvement suggestions are displayed,
    based on which criteria the password failed.
  - If the input field is empty, the user sees an alert message.

FR2 — Password Generator
  - The user can click "Generate Password" to create a new
    random password.
  - The generated password is between 12 and 20 characters long
    (the exact length is randomly chosen each time).
  - The password is drawn from 80 characters:
      lowercase letters, uppercase letters, digits, and symbols
      ( ! @ # $ % ^ & * ( ) - _ = + [ ] { } )
  - Random selection uses the browser's built-in
    crypto.getRandomValues() function with rejection sampling
    to avoid modulo bias.
  - The generated password is displayed on screen.
  - A "Copy" button copies the password to the clipboard using
    the browser's navigator.clipboard API.
  - A "Copied!" confirmation message appears for 2 seconds after
    a successful copy.
  - If clipboard access is unavailable or copying fails, the
    user sees a manual-copy message.

FR3 — Password Security Tips
  - Five static password security tips are always visible:
      1. Use long passwords (at least 12 characters).
      2. Avoid common words and predictable patterns.
      3. Never reuse the same password across accounts.
      4. Use a password manager.
      5. Enable two-factor authentication (2FA).


--------------------------------------------------------------
5. NON-FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------
NFR1 — Privacy
  No password entered or generated is ever saved, stored,
  transmitted, or logged. All processing happens locally
  inside the user's browser.

NFR2 — Performance
  The application must respond instantly to user actions
  (button clicks). There is no network call, so there is
  no loading delay.

NFR3 — Usability
  The interface must be clean, readable, and easy to use
  for someone with no technical background. Interactive controls
  have accessible names and status feedback for assistive technology.

NFR4 — Compatibility
  The website must work in any modern web browser
  (Chrome, Firefox, Edge, Safari) without any installation
  or plugin.

NFR5 — Responsiveness
  The layout must display correctly on both desktop screens
  and mobile phones. The card layout becomes a single column
  at viewport widths of 680px or less.

NFR6 — No External Dependencies
  The project must not use any external libraries, CDN links,
  frameworks, or third-party services. It uses built-in browser
  APIs (Web Crypto and Clipboard); password analysis and
  generation work offline after the files are downloaded.


--------------------------------------------------------------
6. HARDWARE REQUIREMENTS
--------------------------------------------------------------
Minimum hardware to run this project:
  - Any device with a modern web browser installed
    (computer, laptop, tablet, or smartphone)
  - No special hardware is required.

Hardware used for development:
  - A standard PC or laptop with a keyboard and mouse
  - Any operating system (Windows, macOS, or Linux)


--------------------------------------------------------------
7. SOFTWARE REQUIREMENTS
--------------------------------------------------------------
To run the project:
  - A modern web browser (Google Chrome, Mozilla Firefox,
    Microsoft Edge, or Apple Safari — any recent version)
  - No server software, database, or runtime is required.

To develop / edit the project:
  - A plain text editor (e.g. VS Code, Notepad++, or Notepad)
  - A web browser for testing


--------------------------------------------------------------
8. TECHNOLOGIES USED
--------------------------------------------------------------
  Technology     Version / Notes
  ----------     ---------------
  HTML5          Semantic markup, SVG inline shield icon,
                 autocomplete="off" on password input
  CSS3           Light theme, CSS Grid and Flexbox layouts,
                 transitions, strength classes, responsive
                 breakpoints, reduced-motion support
  JavaScript     Vanilla ES6+, DOM manipulation,
                 Web Crypto API (crypto.getRandomValues),
                 rejection sampling, navigator.clipboard API,
                 regex for character and predictable-pattern
                 detection, accessible status feedback


--------------------------------------------------------------
9. SCOPE OF THE PROJECT
--------------------------------------------------------------
In scope:
  - Client-side password strength analysis
  - Visual strength feedback (bar + label + suggestions)
  - Secure client-side password generation
  - Clipboard copy functionality
  - Static security tips display
  - Mobile-friendly responsive design

Out of scope:
  - User accounts, login, or registration
  - Any server, database, or cloud storage
  - Password storage or management
  - Network communication of any kind
  - Integration with third-party password breach databases


--------------------------------------------------------------
10. LIMITATIONS
--------------------------------------------------------------
  - The checker uses basic character-type scoring and a small
    list of predictable patterns; it is only an estimate and
    may miss other guessable passwords.
  - The project does not check whether a password appears in
    breached-password databases.
  - Clipboard access may be blocked when opened as a local file
    (file://) in some browsers; the page reports this and asks
    the user to copy the password manually.
  - The website is in English only; there is no
    multi-language support.
  - The project has no backend, so it cannot enforce any
    real security policy.
